# دليل التست الشامل — للجلسة اللي بتشتغل على جهاز صاحب المشروع (ويندوز)

**متى يُقرأ:** لما صاحب المشروع يقول "اعمل تست كامل" (أو أي صيغة مشابهة) بجلسة شغّالة على جهازه.
هالملف لحاله كافي — ما في داعي يشرح إشي زيادة. اقرأ `CLAUDE.md` كمان (بيتحمّل تلقائيًا) عشان القواعد
العامة، وبعدين نفّذ هون بالترتيب.

**الهدف (بكلام صاحب المشروع):** "بدي تتأكد إن العمليات اللي بتصير صحيحة وفقط" — قبل ما يفكّر يفتح
البقالة. يعني: كل عملية (بيع، إرجاع، إلغاء، شراء، تلف، جرد، تقفيل، أوفلاين، طلبات تطبيق الزبائن)
لازم تنعكس صح على المخزون والمبيعات والربح والصندوق والتقارير والتنبيهات. **الأجهزة مش مهمة** (فيزا،
سكانر، طابعة) — لا تضيّع وقت عليها.

## 0. قواعد ثابتة لهاي الجلسة

1. **القاعدة (Somee) للتست بس — مؤكَّد من صاحب المشروع (25/9/2026): "كله تست حاليًا، معنديش بقالة".**
   اكتب عليها براحتك وطبّق عليها Migrations بلا ما تسأل. (§1.4 بتضل: لا تحذف القاعدة كحل لمشكلة.)
2. **الـConnection String ما بينلمس بالملفات (§1.1).** لا `appsettings.json` ولا `AppDbContextFactory.cs`.
   الوصول على Somee بمتغيّر بيئة بشِل الجلسة بس (تحت). ولا تطبع كلمة سر القاعدة بالمحادثة.
3. **لا `git push` ولا commit بلا إذن صاحب المشروع.** أي أداة مساعدة (FlaUI...) بمجلد مؤقت برّا الريبو —
   ولا حزمة جديدة بمشاريع الريبو (§1.2).
4. **الأخطاء:** سجّل كل خطأ بدليل (الخطوات، المتوقع، الفعلي، صورة/رد الـAPI). خطأ **صغير وواضح بيوقّف
   التست نفسه** — صلّحه وكمّل، واذكره بالتقرير. **غير هيك: لا تصلّح** — اكتبه بالتقرير وصاحب المشروع
   بيقرر (نفس أسلوبه دايمًا: "احكيلي قبل ما تعمل شي").
5. التواصل بالعامية الأردنية. تقرير واحد مرتّب بالآخر (قسم 8)، مش تعليق على كل خطوة.
6. **خلال أتمتة شاشات الكاشير**، نبّه صاحب المشروع ما يلمس الماوس/الكيبورد.

## 2. التجهيز

```powershell
git checkout main; git pull
```

**متغيّرات البيئة (بنفس الشِل اللي بيشغّل الـAPI):**
```powershell
# 1) الـConnection String تبع Somee: غالبًا موجود أصلًا بـSupermarketSystem.API/appsettings.json المحلي
#    (update-database.bat بيكتبه هناك). لو فيه "somee" استخدمه كما هو. لو لأ: اطلبه من صاحب المشروع مرة وحدة.
$env:ConnectionStrings__DefaultConnection = "<connection string تبع Somee>"
# 2) مفتاح التوكن - فاضي بالريبو عمدًا، والـAPI بيرفض يشتغل بلاه. لو صاحب المشروع مش ضابطه كمتغيّر بيئة دائم:
$env:Jwt__SigningKey = "<أي نص عشوائي 32 حرف أو أكتر>"
# 3) تطبيق الزبائن على Chrome (بورت ثابت 5300) - غير هيك المتصفح بيرفض طلباته (CORS):
$env:Cors__AdditionalOrigins__0 = "http://localhost:5300"
```

**الـMigrations:**
```powershell
dotnet ef database update --project SupermarketSystem.Infrastructure --startup-project SupermarketSystem.API --connection $env:ConnectionStrings__DefaultConnection
```

**تشغيل الـAPI** (بالخلفية، بنفس الشِل):
```powershell
dotnet run --project SupermarketSystem.API --launch-profile http   # http://localhost:5200 (Swagger على /swagger)
```
فحص: `GET http://localhost:5200/api/v1/auth/branches` → 200.

**بيانات التست** (أداة جاهزة، مجرَّبة على قاعدة فاضية 25/9/2026):
```powershell
dotnet run --project tools/TestDataSeeder -- --api http://localhost:5200
```
- على قاعدة فاضية بتعمل أول أدمن (`admin` / `123`) وبعدين كل شي تحت. لو البيانات موجودة (تصنيف "بيانات تست")
  بتطلع بلا تكرار.
- لو القاعدة فيها مستخدمين قدام وكلمة سر admin مش `123` → اسأل صاحب المشروع.

**لوحة الإدارة:**
```powershell
cd SupermarketSystem.AdminWeb; npm ci; npx ng serve   # http://localhost:4200
```
للفحص البصري: Playwright (`npx playwright install chromium` بمجلد مؤقت) + صور شاشة.

**الكاشير (WPF):**
```powershell
dotnet build SupermarketSystem.CashierApp
# بداية نظيفة (تست بس): احذف %LocalAppData%\SupermarketSystem.CashierApp\local.db لو موجود
```
`appsettings.json` تبعه أصلًا على `http://localhost:5200/api/v1`.

**تطبيق الزبائن (Flutter)** — ما فيه دعم ويندوز، بيشتغل على Chrome:
```powershell
cd SupermarketSystem.CustomerApp; flutter pub get
flutter run -d chrome --web-port 5300 --dart-define=API_BASE_URL=http://localhost:5200/api/v1
```

## 4. كيف تسوق شاشات الكاشير

- كل عنصر مهم إلو `x:Name` بالـXAML (`Views/*.xaml`) = `AutomationId` بـUI Automation. اقرأ الـXAML أول.
  أمثلة: `UsernameBox`، `PasswordBox`، `LoginButton`، `StartSaleButton`، `BarcodeBox`، `CartGrid`،
  `TotalText`، `TenderedAmountBox`، `PaymentMethodCombo`، `CompleteSaleButton`، `SyncNowButton`،
  `ConnectionStatusText`، `QueueGrid`، `ReturnButton`، `VoidSaleButton`، `CashClosingButton`، `CountedCashBox`.
- الأداة: مشروع console مؤقت (برّا الريبو، مثلًا `%TEMP%\cashier-driver`) مع `FlaUI.UIA3`، أو `pywinauto`.

- التحقق الحقيقي دايمًا من الـAPI/لوحة الإدارة بعد العملية — مش بس من شاشة الكاشير.

## 5. السيناريوهات (بالترتيب — كل رقم متوقع محسوب من بيانات قسم 3)

> سجّل رقم كل فاتورة وكل مبلغ فعلي — قسم 7 بيطابقهم كلهم مع بعض بالآخر.

### أ. الكاشير أونلاين (`cashier1`)
1. دخول + مزامنة: الكتالوج فيه الـ5 منتجات. بحث بالاسم ("حليب") وبالباركود بيلاقيهم.
2. **بيع 1:** 2 رز = **7.000** كاش (دفع 10 → الباقي 3.000). مخزون الرز 20 → 18.
3. **بيع 2:** كرتونة حليب (باركود ...028) = **15.000** كاش. الحليب 48 → 36.
4. **بيع 3 (عرض):** 3 مياه → المتوقع **0.900**. ⚠️ خطأ معروف (قسم 6): الكاشير بيحسب 1.050 والسيرفر بيرفض
   (422 `PaymentsExceedTotal`) والبيع بيعلق بالطابور. **أكّده وسجّله** (بدليل)، وبعدين احذفه من الطابور أو خلّيه
   وكمّل. وجرّب نفس البيع من Swagger/الـAPI مباشرة: 3 مياه بدفعة 0.900 لازم ينجح (السيرفر نفسه سليم).
5. **بيع 4:** شيبس واحد 0.250 **فيزا**.
6. **إرجاع:** من بيع 1، رز واحد → استرجاع 3.500 كاش. الرز 18 → 19. بيطلع تنبيه "إرجاع" (مهم) وبالمراجعات.
7. **إلغاء:** بيع لبن واحد (1.900) وبعدين إلغاؤه → المخزون بيرجع 10، تنبيه "إلغاء".

### ب. الأوفلاين (أهم قسم — ما انجرّب على ويندوز أبدًا)
1. **طفّي الـAPI** (أوقف العملية). شاشة الكاشير لازم تبين إنه أوفلاين (`ConnectionStatusText`).
2. البحث بالاسم والباركود لسه شغّال (محلي).
3. **بيع 5 أوفلاين:** 2 حليب = 2.500 كاش → بيتحفظ محليًا وبيطلع بالطابور (1 معلّق).
4. سكّر تطبيق الكاشير وافتحه (والـAPI لسه طافي) → البيع المعلّق **لسه موجود**.
5. **تغيير سعر والكاشير متأخر:** قبل ما تشغّل الـAPI، ارفع `SyncIntervalSeconds` بنسخة
   `appsettings.json` **جوّا مجلد bin** تبع الكاشير (مش ملف الريبو) لـ600، وأعد فتح الكاشير. شغّل الـAPI،
   وفورًا من لوحة الإدارة غيّر سعر الحليب بالرئيسي لـ1.400 (الأدمن عنده صلاحية التغيير المباشر، فبيتطبّق فورًا بلا موافقة). بعدين من الكاشير "مزامنة الآن".
   - المتوقع: البيع المعلّق **بينقبل بالسعر القديم** (2 × 1.250 = 2.500)، ومعلَّم للمراجعة (بيع بسعر مش
     الحالي) + تنبيه. بعد المزامنة الكاشير بيعرض الحليب 1.400.
   - رجّع `SyncIntervalSeconds` لـ60 بالآخر.
6. بيع بعد المزامنة: حليب واحد = **1.400**.

### ج. تقفيل الصندوق (`cashier1`)
- المتوقع = كل الكاش المقبوض − الاسترجاع الكاش (احسبه من الفواتير الفعلية اللي انعملت، مش من هالملف).
- عدّ أقل من المتوقع بـ0.500 → لازم يطلع **عجز 0.500** + تنبيه **خطير** (🔴).

### د. لوحة الإدارة (`admin`) — كل إشي لازم يطابق اللي فوق
1. **المبيعات:** كل الفواتير بحالتها الصح (مرتجعة جزئيًا، ملغاة...). ملخّص المبيعات = مجموعها.
2. **المخزون الحالي** لكل منتج = الحساب بقسم 7.
3. **التقارير:** قرب انتهاء الصلاحية (اللبن L-001)، إعادة الطلب (الشيبس)، استحقاق دفعة مورد (فاتورة الشراء)،
   الإرجاعات، الملغاة، هامش الربح لكل منتج (إيراد − تكلفة بالتكاليف فوق).
4. **تلف:** 2 حليب "مكسور" مش مستبدَل → بكشف الربح خسارة تلف **1.600** (2 × 0.800). وتلف تاني "مستبدَل من
   الشركة" → بينقص المخزون بس **مش خسارة**.
5. **ضيافة:** حليب واحد.
6. **جرد جزئي/كامل للرز:** عدّ أقل من النظام بـ1 → نقص بالجرد (تنبيه **خطير**)، وبكشف الربح نقص **2.600**.
7. **تحويل بين الفروع:** 10 حليب من الرئيسي لفرع 2 واستلامها. دخول `cashier2` بالكاشير → بيع حليب بـ**1.300**
   (سعر فرع 2). تكلفة الدفعة المنقولة لازم تضل 0.800 (مش صفر).
8. **دفعة للمورد:** 50.000 → الباقي 66.150.
9. **طلب تغيير سعر** من `assistant1` وموافقة `admin` (تنزيل سعر → تنبيه "تنزيل سعر").
10. **مصروف** (كهرباء 20.000 للشهر) → بينزل من صافي الربح.
11. **كشف الربح الشهري للرئيسي:** تحقّق من كل بند يدويًا:
    `صافي الربح = (صافي الإيراد − تكلفة البضاعة) − المصاريف + فائض الجرد − نقص الجرد − خسارة التلف`.
12. **التنبيهات:** فلتر "الخطيرة بس" بيبين العجز ونقص الجرد؛ كل النصوص عربي (بلا أسماء إنجليزية أو GUIDs).
13. **المراجعات:** الإرجاع والبيع بالسعر القديم بيبينوا؛ "تمت المراجعة" بيشيلهم فعليًا (بعد تحديث الصفحة).
14. **طرد:** من "الجلسات" ألغِ جلسة `cashier1` → أي طلب من الكاشير بياخد 401. (معروف: الشاشة ما بترجع لحالها
    لشاشة الدخول — أكّد إنه البيعات المعلّقة ما بتنضيع.) وتعطيل مستخدم بيطرده فورًا.
15. **بيع بالدين:** من الـAPI بس (زر الكاشير مش مبني): `allowCreditSale: true` + `customerId` (زبون تطبيق
    الزبائن من قسم هـ) بدفعة ناقصة → بيبين بـ"ديون الزبائن"، وتسديد لاحق بيصفّره.

### هـ. تطبيق الزبائن (Flutter على Chrome)
**الدخول:** كود OTP بيوصل بتلغرام بس. إذا صاحب المشروع ما عنده بوت مضبوط، الطريقة (قاعدة تست بس):
```powershell
# خطوة 1 (مرة وحدة): اربط رقم الزبون بمحادثة تلغرام وهمية
#   INSERT INTO TelegramChatLinks(Id, Phone, ChatId, LinkedAtUtc) VALUES (NEWID(), '0790000001', '0', SYSUTCDATETIME())
# خطوة 2: من التطبيق اطلب كود للرقم 0790000001 (الإرسال لتلغرام بيفشل بصمت - عادي)
# خطوة 3: خلّي الكود 123456:
#   UPDATE CustomerOtpCodes SET CodeHash = 'jZae727K08KaOmKSgOaGzww/XVqGr/PKEgIMkjrcbJI=' WHERE Phone = '0790000001' AND IsUsed = 0
# خطوة 4: ادخل الكود 123456 بالتطبيق
```
(`sqlcmd` لو موجود، أو PowerShell بـ`System.Data.SqlClient.SqlConnection` بنفس `$env:ConnectionStrings__DefaultConnection`.
مجرَّبة عبر الـAPI 25/9/2026.)

**السيناريو:**
1. اختيار الفرع الرئيسي → الكتالوج بيبين المنتجات بأسعار الفرع.
2. سلة + طلب (حليب 2 + رز 1).
3. لوحة الإدارة → "طلبات الزبائن": قبول → تعيين `driver1` → إكمال. الطلب لازم يصير فاتورة بيع، والمخزون ينقص،
   والمبيعات تزيد.
4. التطبيق بيبين حالة الطلب صح بكل مرحلة، والتقييم بيشتغل، ورصيد الولاء بيتحدّث، والشكوى بتوصل.

## 6. أخطاء/فجوات معروفة — أكّدها، ما تعتبرها اكتشاف جديد
1. الكاشير ما بيطبّق عروض الكمية → البيع بينرفض (سيناريو أ-4).
2. لوحة الإدارة بتعرض المبالغ بخانتين بدل ثلاث (0.125 → 0.13)، وما في رمز "د.أ".
3. لوحة الإدارة على الموبايل مكسورة.
4. الكتالوج بيعرض السعر المقترح مش سعر الفرع.
5. الكاشير المطرود ما بيرجع لشاشة الدخول لحاله.
6. ما في "تعليم كمقروء" للتنبيهات.
7. ما في زر "بيع بالدين" بالكاشير.
8. طرق الدفع بالكاشير بدها اتصال أول مرة بكل جلسة.
9. شكلي: الـAPI بيرجّع `totalAmount` بخانات كتير (`7.0000000000`).

## 7. المطابقة النهائية (لازم كلها تطلع صح)
- **المخزون لكل منتج/فرع** = شراء − مبيع + مرتجع − تلف (المستبدَل كمان) − ضيافة − محوَّل للخارج + محوَّل للداخل ± فرق الجرد.
  (الفواتير الملغاة ما بتنحسب مبيع.)
- **ملخّص المبيعات** = مجموع الفواتير غير الملغاة − المرتجع.
- **كشف الربح** = المعادلة بـد-11، وكل تكلفة من التكاليف بقسم 3.
- **المتوقع بالتقفيل** = الكاش الفعلي بالدرج.
- **دين المورد** = 116.150 − المدفوع.
- **عدد التنبيهات ودرجتها** = الأحداث اللي صارت (جدول التنبيهات بـCLAUDE.md).

## 8. التقرير
- اكتبه بـ`docs/test-runs/YYYY-MM-DD.md` (بالعربي) — الصور تضل محلية، ما بتنرفع.
- جدول: السيناريو | النتيجة (✅/❌/⚠️ معروف) | المتوقع | الفعلي.
- لكل ❌: خطوات إعادة الإنتاج + الدليل + اقتراح الإصلاح (بلا تنفيذ إلا لو قسم 0-4 بيسمح).
- بالآخر للمستخدم: ملخّص قصير بالعامية + شو بتقترح نصلّح أول. واسأله قبل أي commit/push.
